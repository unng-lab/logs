# Руководство по работе с репозиторием

Добро пожаловать в Flutter-проект SSH Systemd Logs. Следуйте этим правилам при работе с репозиторием:

## Рабочий процесс
- Используйте Flutter 3.19+ и Dart 3 при запуске команд.
- После изменения зависимостей выполняйте `flutter pub get`.
- Перед коммитом форматируйте код Dart через `dart format lib test`.
- При изменении исходного кода или логики запускайте `flutter analyze` и `flutter test`.
- Не добавляйте в логи, тесты и репозиторий учетные данные, приватные ключи и данные о хостах.

## Советы по стилю
- Используйте Riverpod-паттерны, уже применяемые в кодовой базе, для управления состоянием.
- Делайте UI реактивным относительно провайдеров; избегайте ручного `setState`, если это не требуется.
- Предпочитайте небольшие виджеты с понятной ответственностью и по возможности переиспользуйте компоненты из `lib/widgets`.

## Заметки по PR и отчетности
- В итоговом описании перечисляйте основные пользовательские изменения и упоминайте ключевые файлы.
- Документируйте запущенные тесты и указывайте их команды в финальном отчете.
- Если менялись только документация или комментарии, тесты можно не запускать, но это нужно явно указать.
